## 已采用的参考状态构造

论文记号 `I_src` 表示从源程序取得的初始状态元组，包含必要的定义域修复；
`I_ref` 表示参考元组，`I` 表示最终维护元组。现有代码和结果字段中的 `A0`、`B`、`A`
分别对应这些记号；代码字段 `reference_B` 保持原名。

`_Select.supplement` 从初始状态的规范化定义收集
`{atom for candidate in base for atom in atoms_in(candidate.state, world.R)}`。
这些原子构成 `I_ref`，初始定义给出已知映射 `I_src = G_src(I_ref)`。
候选过滤、SyGuS 规约和完整恢复验证使用这一参考表示。
所需输出在归约器推导与生成时从选定状态重构；输出定义不向参考元组加入分量。

第四章的 `Q` 来自存在性分析，给出一种单遍融合构造的充分状态数上界，
其数量用于设置默认状态限制；它不必等于此处的参考归约集合。
这个上界不是最少状态数，也不保证保留源状态的表示一定能在该限制内找到。

### 实际参考状态的程序生成

现有 `numerical_audit.programs.reference_programs` 按以下过程生成方差和 softmax 的对照程序：

1. 取 registry 中该算子的原 TE 输入与输出，发现唯一归约链，运行一次 `_Select`。
2. 从同一 selector 取得完成修复的 `base()`，收集其定义中的 `atoms_in(candidate.state, world.R)`。
3. 将排序后的完整原子元组作为 `B_atoms`，保存其定义和顺序；所需输出不扩充这些原子。
4. 使用 `derive(B_atoms, required_full, chain.axis, preserve=True)`，独立证明结果重建表达式。
5. 分别通过 `build_chain` 和独立的 `Rewriter` 生成 `reference_B` 程序和同次选择所得的维护状态程序。

对照对象是选择器实际使用的参考元组；结果检查应核对它与 `I_ref` 的分量一致。

必须保留参考元组的全部分量及生成的结果重建表达式：

| 算子 | I_ref 的分量 | 重建方式 |
| --- | --- | --- |
| 方差 | sum(x), sum(x²), count | ss = sum(x²) - sum(x)²/m，再保留原输出 var = ss/m |
| softmax | max(x), sum(exp(x)) | den = sum(exp(x)) * exp(-max(x))，再保留原输出 exp(x-max(x))/den |

`preserve=True` 确保方差的 count 不因最终表达式使用全轴长度 m 而被删去。
softmax 不能手工约成 `exp(x)/sum(exp(x))`，这会改变浮点实验对象。
参考状态版本必须直接执行；将它先送入 AccuracyGate 会因无界指数等静态条件被拒绝，导致未测量。
静态检查诊断可另行记录。

## 预先固定的代表性实验

- 形状 `(3,m)`，m 为 16、256、4096；随机种子 0、1、2。
- 基础数据从整数 [-16,16] 除以 8 得到，每行强制包含 -2、0、2，再按种子打乱。
  对同一尺寸和种子复用基础数据，三种实现始终使用相同的实际 float32 数组。
- 方差偏移扫描（尺度 1）：0、1、16、256、4096、10000、65536、1048576。
  此范围保留 1/8 网格，避免将输入离散程度因量化消失误认为算法消去。
- softmax 偏移扫描（尺度 1）：-128、-112、-104、-96、-88、-64、0、64、80、88、96、128、10000。
- 方差尺度扫描（偏移 0）：2 的 -80、-70、-60、-30、0、30、60、65、70 次方。
- softmax 尺度扫描（偏移 0）：1/16、1、4、16、32、64、128。
- 单独测试单元素、全零和常量输入。

保留源程序失败、维护状态更差、NaN/Inf、域外输入和 MPFR 未收敛等结果。
有限误差与非有限结果数量分别报告；零参考结果使用绝对误差并标注是否精确相等。
不要把失败样本从分母中删除。

第一项比较检验上下文分析提供的候选是否帮助搜索；第二项比较检验恢复语义约束对
proposal 生成的作用；第三项比较检验组合候选与单独选择候选的区别。
四种模式均使用相同的独立恢复、定义域和 join checker，不联合综合任意的 `C,H,join`。

使用单一 mixed grammar 阶段作为共同调度框架；“仅参考候选”只替换其 terminals。
否则删除 preferred 阶段会改变现有实现的时间分片，无法单独解释候选池的影响。
统一实际状态上限、width 次序 `[max_extra, 1, ..., max_extra-1]`、求解器版本及配置、
256 个 proposal 上限和 20 秒总搜索时间；除单项模式外，均允许最多 3 项的加减组合。
记录实际每个 width 的限时、solver 调用限时、checker 耗时和整体墙钟时间。
这些是相同资源上限下的启发式比较，不是完备性或最少状态数实验。

受控 semantic 模式遇到 unknown 时记录原因，不悄悄切换为枚举；
枚举模式从同一 grammar 原生生成候选，并通过同一独立 checker。
不要将 solver 内部反例次数与送到 checker 的 proposal 数混为一谈。
生产模式的回退保持不变，另外记录其发生阶段。

候选抑制只发生在修复完成后的 supplement 候选池。
特别不能全局禁用 `_Chain.pieces`：它也参与源状态定义域修复，会改变比较对象。
保持候选稳定排序、去重和结构形式保存方式一致；记录各模式实际差异。

### 任务 C：固定表示下比较 join 的求值形式

对同一次选择得到且已认证的维护状态固定 `I`、初始化和输出重建，比较：

1. 默认的已验证打印 join。
2. 关闭 rebase merge printing 后的代数 join。

第二种只能称为“关闭 rebase merge printing”。`finish` 在调用 `derive` 时已经传入
`Printer.kept`，因此代数 join 本身可能保留部分局部上下文；不能将此对照称为
“移除所有数值稳定化”或“直接执行原始参考状态”。
先保存并对照实际发射表达式；若两者相同，明确标记该 case 没有发生求值形式变化。

两个版本沿用同一静态检查、结果重建和数值验收规则，记录在哪个阶段被拒绝以及哪些阶段未执行。
不要关闭验收以增加通过数，也不要因拒绝而重新选择另一组状态；
即使文末的继续搜索扩展已经实现，此固定表示对照仍须关闭该扩展。
运行数值比较时复用前述相同输入、MPFR 参考、编译参数和报告格式。
参考状态 `I_ref` 与维护状态的实际程序比较仍按前面的独立实验执行，不能用此固定 `I` 对照替代。

### 任务 D：验证、交付与可支持的结论

为诊断和实验控制增加最小必要测试，至少覆盖：

- 关闭实验模式时，与记录提交的生产基线具有相同的选择、发射表达式和验收结果。
- 方差的辅助 count；需要组合候选的情况；有条件恢复；源定义域修复。
- 多链中仅部分成功；完整数值拒绝报告；unknown、状态上限及资源耗尽的区分。
- 受控模式拥有相同修复结果与 checker；unknown 不跨入另一 proposal 模式。
- 固定 `I` 的求值形式对照未改变状态定义、初始化、输出重建或验收参数。

已有 `6c46fb1b02` 快照可用于选择有代表性的链和核对字段，不能充当新受控比较的数据。
尤其不能从某个旧 case 走了 SyGuS 路径，就推断所有仅靠上下文修正的方法都会失败。

交付代码提交、完整配置和依赖版本 manifest、每链/每模式结果、全部状态与 join 表达式、
测试日志、字段说明及一条重现命令。建议在已有结果包下增加 `state_selection/`，保存
`chains.jsonl`、`attempts.jsonl`、`summary.csv` 和表达式文件，使用稳定链 ID 关联数值结果。
汇总同时报告覆盖数、完整融合数、proposal/checker 次数和分阶段耗时；
分别报告资源耗尽和证明失败，保留所有相同、变差或未观测到收益的结果。

论文可以根据实现说明综合只搜索辅助状态、join 由恢复构造；参考候选对覆盖、语义约束对搜索成本、
打印 join 对精度的影响，则由这些受控实验评估，不预先断言收益。完整恢复是当前方法选择的充分条件；
若另一方法能直接证明整个维护元组的 join 不变量及输出与定义域，也可能不需要该条件。
本组比较不回答这种替代方法的优劣；它衡量的是当前方法内部各机制的实际作用。

## 独立扩展：执行验收拒绝后继续搜索

本节是交给开发 agent 的实施任务，当前代码尚未提供该功能。
它复用已经存在的辅助状态综合器、恢复验证和精度 gate，不重新设计参考状态来源或证明规则。
目标是在第一个代数正确的归约器未通过执行验收时，继续尝试当前搜索范围内的后续候选。

### 接口与候选接受流程

在公开入口 `fuse` 增加关键字参数 `retry_rejected_candidates: bool = False`。
默认关闭时必须保持原生产行为，包括候选次序、停止位置、发射表达式和各精度模式的语义。
启用后，为 `select`/`_Select` 提供可选的 `accept_candidate(Solution) -> bool` 回调；
未提供回调的独立 `select` 调用仍在第一个通过代数验证的候选处结束。

回调挂接在 `_Select.supplement` 的 `recover(trial)` 内：
`finish(trial)` 已生成有证明的 `Solution` 之后、将结果赋给 `self.prepared` 之前。
同一个挂接点覆盖初始源状态、完整修正系数补充和 SyGuS 候选，不能只扩展最后一条路径。
返回 `False` 表示拒绝当前候选，不提交该候选的状态；原有 proposal 循环继续。
使用 `checkSynthNext()` 或已启用枚举路径的 `findSynthNext()`，不要重新调用整个 `select`
并再次取得同一个首选结果。原有 quantified synthesis 的 unknown 后枚举回退保持不变；
数值拒绝本身不改变这项回退策略。

由 fusion 层实现回调，按现有次序执行静态检查、TE 重建、小输入一致性检查和数值验收。
每次尝试都从该链开始前的已提交 `Rewriter` 调用 `fork()`，构建完整候选输出。
只有回调接受候选后才提交对应 fork；拒绝或异常不得改变输入 rewriter，也不能撤销之前已接受的其他链。
返回并报告的状态名称要与选择器最终接受的状态对应，不能依赖补充过程中尚未规范化的临时名称。

`accuracy="filter"` 继续要求通过现有静态和数值验收；拒绝后尝试下一个候选。
`accuracy="report"` 仍接受代数与重建检查通过的候选并附加数值报告，即使其数值报告不通过，
不因该报告触发重试。`accuracy="off"` 仍跳过精度 gate，保留现有重建一致性检查。
开启继续搜索后，静态检查、TE 构建或重建一致性失败也拒绝当前候选并继续。
所有路径耗尽后保留该链的原程序，输出报告区分没有代数解与已有代数解但执行验收未通过。

### 复用检查与控制开销

为同一次 `fuse` 调用复用同一 `AccuracyGate` 和 `_Agreement`。
使用 gate 已保存的实际量化输入、MPFR 结果、源执行结果、敏感性及参考精度，
后续候选必须在相同 case 上受验收，不得通过换种子或删除失败 case 得到接受。
本扩展不新增根据数值失败自动生成输入或改变文法的学习器；如果后续另行引入失败输入，
这些输入必须保留并重放给所有后续候选。

在编译前对已发射的候选进行去重，指纹包括初始化、实际 join 求值表达式、输出重建、dtype、
编译配置及该链输入重写状态。可规范化局部变量名，但不能用代数等价规范化代替表达式指纹：
两个实数等价的求值形式可能有不同浮点行为。重复程序复用其验收结果，并记录为重复尝试。

沿用综合阶段至多 256 个 proposal 和共享 20 秒截止时间，不在数值拒绝后重置。
回调内的代码生成、编译及检查时间计入该综合阶段墙钟时间；超过截止时间后不启动新的尝试，
正在进行的证明或执行检查允许完成并记录超时幅度。
前置的源状态和完整系数候选各最多尝试一次，仍在该综合阶段之前，分别记录其完整开销。
重复 proposal 仍计入 proposal 上限；它们不能通过去重绕开有限搜索限制。
完整耗时报告同时列出前置候选、综合、证明、代码生成和数值验收，不把 20 秒称为端到端硬上限。

### 诊断、测试与对照

每次尝试沿用稳定链 ID，补充 proposal ID、来源、发射指纹、代数检查结果、执行阶段状态、
数值完整报告、拒绝原因和各阶段耗时。给精度失败保存 case ID、输入哈希和输出名称；
若能定位失败元素则同时记录索引。共享输入保存在结果包中，不能仅保留汇总误差文字。
已证明但精度失败的候选必须记录为 `numerical_rejection`，不能沿用 `unproved`。
结果中分别统计 proposal 数、独立证明数、唯一发射程序数和实际数值验收数。

最小必要测试应覆盖：

- 默认关闭时与未扩展基线一致；没有回调的 `select` 仍返回第一个有证明的结果。
- 第一候选已证明但数值失败，第二候选通过；两者都经过同一组数值输入。
- 初始元组和完整系数两条快捷路径被拒绝后均能继续，SyGuS 及枚举继续接口也接受该反馈。
- 全部候选被拒绝、资源耗尽、未知结果和重复发射程序，均能终止并保留源链及完整拒绝记录。
- 失败的 fork 不污染后续候选和已接受的其他链，最终提交结果对应实际接受的候选。
- 数值拒绝不重置时间和 proposal 限制；计时测试采用可控时钟与桩回调。
- `report` 模式的数值失败不触发重试，`off` 模式不调用精度 gate；源状态修复与完整恢复规则不变。

增加独立的继续搜索实验：在相同开发提交上，仅切换 `retry_rejected_candidates`，
保持链、定义域、源/参考状态、候选文法、状态上限、候选次序、编译设置、量化输入和验收阈值不变。
报告首次候选的拒绝阶段、最终接受的候选序号、完整融合覆盖、每链接受率和端到端额外时间。
另外列出未发生拒绝、继续搜索仍未找到候选以及资源耗尽的情况。
这项实验允许最终状态改变，必须与任务 C 的固定 `I` 求值形式对照分别运行、分别制表。
两种模式均在一次预热之后重复五次，报告中位耗时及每次选择/验收结果，不能只保留成功运行。

该功能属于经验性验收驱动的候选继续搜索。数值失败由 gate 重放，未被编码为 cvc5 的
实数恢复规约，因此不能称为新的应用层 CEGIS，也不能据此宣称浮点正确性已经形式化证明。

## 证据、论文主张与接收条件

| 论文主张 | 所需依据与允许的表述 |
| --- | --- |
| 无需独立综合 join | 已知参考合并与完整恢复构造；可说明综合未知量只有辅助表达式，`H` 另行构造验证 |
| 源状态与修正候选限制搜索 | 实现固定 `I_src`、采用有限候选文法；可说明减少自由选择的状态表达式，不宣称保留全部有效解 |
| 上下文候选帮助搜索 | 任务 B 的相同资源比较；报告覆盖、proposal/checker 次数和耗时，数据产生前不写“显著加速” |
| 源结构有助于数值表现 | 实际参考/维护/源程序三方对照及任务 C；保留变差结果，避免从代数定义直接推断稳定性 |
| 继续搜索改善接受覆盖 | 新扩展启用/关闭的独立对照；同时报告额外编译、检查和搜索开销 |
| 对一般状态或 join 综合更优 | 上述实验不支持该结论；没有直接 join 综合或取消源状态固定的对照 |

“仅参考候选”仍固定源状态，不能称为取消源状态保留的消融。
修正系数作为终结项可能表达复杂的非线性量；加入它们也可能增加终结项数量，
因此不能将该比较简单解释为候选文法基数变小。
更广泛的参考状态非线性组合也可能给出良好的维护表示，其数值表现取决于实际求值公式。
本方法的限制有结构和数值动机，收益大小由实验回答。

论文侧先完成已有方法的动机、问题分解与搜索限制重写。
所有当前基线的新消融、MPFR 对比及继续搜索结果均处于待交付状态。
只有在收到扩展代码提交、上述测试日志、开启/关闭的可复现实验包，并核对实际控制流后，
才将第五章算法、系统流程图、第六至七章的失败处理更新为包含执行验收反馈的实现。
此时保留开关默认值和测量配置，明确区分原生产基线与可选扩展。
新增贡献或摘要中的精度、覆盖和搜索收益陈述须逐项链接到对应数据；
扩展尚未完成不阻塞当前论文重写，也不以未来设计替换现有实现事实。
